# @effect-harness/durable

Committed conversation state and executor Layers for native Effect Workflow. Public subpaths include `/Record`, `/Store`, `/Session`, `/Document`, `/Conversation`, `/Inbox`, `/Usage`, `/View`, `/Event`, `/Inspection`, `/Ownership`, `/Executor`, `/storage/Memory`, `/storage/Jsonl` and `/storage/Sqlite`.

Build a scoped Store Layer, a `Session.layer`, and `SessionDirectory.layerSingle(sessionId)` or a directory of already scoped sessions. Provide `Conversation.layerCreation` while constructing Session to install built-in documents and conversation creation hooks atomically. `Conversation.layerConfiguration` supplies settings and host callbacks; provide your Registry to creation when using its `conversationCreated` hooks. Root conversation ID `1` is reserved and created lazily by `session.root()`.

`Conversation` offers root/create/fork/configure/context operations. Agent configuration is inherited on conversation creation/fork; a fork selects entries and document history at its cutoff. Context follows the active head, reset and compaction edits. The Inbox applies input/write submissions at admission, tool and final boundaries, with explicit steer/follow-up/reject behavior for busy conversations. Usage remains committed domain state. `Conversation.awaitIdle(session, id?)` waits for non-background owned work using declared native executions; it requires Ownership.Declarations and WorkflowEngine. Omitting the ID selects ownerless conversation roots.

`Executor.layer` registers Submission, Generation, ToolCall, Compaction and Abort with your native WorkflowEngine. Use the declarations' native `execute`, `poll` and `resume` methods. To extend owned work with your own Workflows, use `Executor.layerExecutors` and an extended `Ownership.layerDeclarations` containing the built-ins. `Structured` helpers inside ordinary Workflow handlers bind and drain owned tasks/conversations; `Cancellation` provides scoped live-body cancellation and committed abort fencing. These helpers do not implement a second Workflow engine.

The [runnable example](../../apps/example/README.md) supplies a genuine SQLite engine and domain Store. [Persistence](../../docs/persistence.md) explains transactions, documents, migrations and receipts; [observations](../../docs/observations.md) explains committed watches. [Custom Workflows](../../docs/workflows.md) describes native authoring and ownership. Live provider streams are external inputs until committed; UI observers read committed domain projections.

`Conversation.layerConfiguration` validates initial policy with typed `SchemaError`; its Configuration service exposes `updateSettings` for validated live replacement. `Session.initialize` uses the captured creation/recovery initializer to repair legacy provider affinity before requests without rerunning creation callbacks. Construct the Session with `Conversation.layerCreation` and its Crypto dependency.

`Session.close` seals admission/observers immediately, shares cleanup across callers, joins registered handler finalizers and then closes backend resources. It pauses native executions for resume rather than generating an abort receipt. Keep the engine alive when reopening a Session. [Lifecycle tests](test/workflow/Lifecycle.test.ts) cover actual harness close/resume with native Memory and SQL-backed Cluster engines.

Public `/Entry` tokens are `UserEntry`, `AssistantEntry`, `SystemEntry`, `ToolResultEntry`, `ResetEntry` and `CompactionEntry`. Each exposes `kind`, an identity-only `is` guard, `schema` and effectful `decode`; decode before trusting stored model/data payloads. Reset decoding validates its self head, and tool-result decoding accepts immediately unavailable settlement metadata. `Record.defineEntry` supports caller-defined kinds. Package-root imports expose concept namespaces, and `/testing/Conformance`, `/testing/Runner`, `/testing/Assertions` and `/testing/Benchmark` expose storage test helpers.

See [parity.md](../../docs/parity.md) for the contract/export-family map, native substitutions and required pinned Effect patch. The patch covers both AI unknown-call settlement and Cluster Activity readiness before SQL transaction acquisition; unpatched external 4.0.1 cannot be assumed to provide either behavior. Native Activity body/reply persistence stays transactional. The pinned behavioral contract has been independently reviewed with executable coverage; the linked scope retains live remote/platform and external unpatched-install limits.
