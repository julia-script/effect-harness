# Persist domain state and native execution

The durable package stores conversation, entry, task and submission records; schema-versioned documents; ordered commit frames; and idempotency receipts. The native WorkflowEngine stores its own messages, activities, deferred results and execution state. Both are needed for restart recovery. A persistent domain Store paired with an in-memory engine cannot restore lost native execution history.

The [public example](../apps/example/src/main.ts) composes `@effect/sql-sqlite-bun/SqliteClient`, native `SingleRunner` and `ClusterWorkflowEngine`, and `durable/storage/Sqlite.layer` against the same database. SQL message storage persists even with memory runner membership. All scopes close at the application boundary. [HarnessRestart.test.ts](../packages/durable/test/restart/HarnessRestart.test.ts) uses fresh processes and killed workers to verify recovery across physical commits; the example checks fresh-process replay after normal completion.

This composition requires the checkout's [native Cluster readiness repair](parity.md#native-cluster-activity-transaction-readiness) in the pinned Effect patch. A recovered Activity RPC waits for its definition before taking the SQL storage transaction; otherwise a Workflow prefix that needs SQL before declaring the Activity can deadlock. Body and reply persistence remain in the native transaction. [The native restart fixture](../packages/durable/test/restart/NativeRestart.test.ts) checks both completed-result reuse and rollback/reexecution after SIGKILL inside the transaction. Do not assume an unpatched external rc.118 installation has the same recovery behavior.

| Domain Store | Layer                                        | Boundary                                                        |
| ------------ | -------------------------------------------- | --------------------------------------------------------------- |
| Memory       | `storage/Memory.layer`                       | Scoped process-local state                                      |
| JSONL        | `storage/Jsonl.layer({ directory, fsync? })` | Native FileSystem and Path; self-contained commit frames        |
| SQLite       | `storage/Sqlite.layer`                       | Native SqlClient; serialized transactions and committed journal |

JSONL is a single-writer store; coordinate ownership externally. It repairs an incomplete final line on reopen, rejects malformed complete frames, and poisons the open store when a write's outcome is uncertain. Reopen to inspect the committed file before continuing. `fsync` controls durable flush behavior; do not infer crash durability when disabling it. SQLite uses validated domain schema migration and native SQL transactions; retain the database's native engine tables too. The formats are harness formats, not interchangeable Pi storage files.

`Session.transaction` accepts an Effect callback with its own typed error channel. It commits all writes atomically, or rolls them back. Query tables before mutating them: subsequent table reads after table writes are rejected, so prefetch the facts needed by the callback. Documents are acquired as mutable transaction drafts, including read-your-own staged changes. Drafts are revoked when the callback ends; return detached values with `Document.copy` while the draft is active. Copying also supports nested immutable JSON data without leaking draft proxies.

Unkeyed transactions preserve arbitrary callback results, including `void`. A transaction with an idempotency key accepts only JSON-safe results or void and stores its replay result atomically with domain writes. An explicit void receipt distinguishes void from JSON null. A replay returns the original result without rerunning the callback. This protects database facts, not arbitrary outside effects; keep those in native Activities and select an honest tool replay policy.

Define a singleton with `Document.define`, or a keyed document with `Document.family`. Definitions declare kind, positive schema version, scope (`session`, `conversation` or `task`), codec and initial value. Conversation documents also declare history (`latest` or `rewindable`) and fork policy (`asOf`, `current` or `initial`); `asOf` requires rewindable history. Scope/owner/family keys determine the address. Pure migration functions lift older content to the declared version; newer stored versions and mismatched definitions fail. A read can project a migration; mutation persists it.

Forks copy visible entry history and apply each document's declared fork policy. `asOf` copies historical content at the fork cutoff, `current` copies present content and `initial` creates fresh initial state. Built-in agent configuration uses historical inheritance; provider affinity starts fresh. Retirement closes a document incarnation, and recreating its address gets a new incarnation. Watchers remain bound to the old incarnation and close when it retires. Terminal task projection retires all task documents atomically.

`Conversation.layerCreation` captures native Crypto for provider-affinity initialization, including a recovery initializer on Session's optional CreationHook. `session.initialize(conversationId)` repairs missing legacy affinity atomically without rerunning conversation-created callbacks. Generation and compaction invoke it before any request. A persisted provider UUID is reused on retry/reopen; it is not the native execution ID, conversation ID or authorization account key. Construct Sessions with the creation Layer when using the built-in executors.

`Store.seal` ends admission and observers while retaining resources needed by cleanup; `Session.close` shares one cleanup operation, joins registered handler finalizers, then closes the backend. A cancelled close waiter does not abandon cleanup. [Close.test.ts](../packages/durable/test/storage/Close.test.ts) and [CloseExecutor.test.ts](../packages/durable/test/workflow/CloseExecutor.test.ts) check the admission/observation fence and blocked cleanup. Reopen uses committed truth; a close is not a task-abort receipt.

SQL observation reads use a committed reader outside the current transaction context. A nested native Activity transaction must physically commit before observers see its frame. No precommit cache or PubSub publication stands in for that fence. Commit journals are bounded and retain relevant document/conversation categories; consumers must resynchronize from a coherent committed snapshot when their own backlog exceeds retention. Use View/Event for UI observation rather than treating the journal as an unlimited audit log.
