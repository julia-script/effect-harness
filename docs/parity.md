# Public contract and parity scope

This page is for TypeScript/Effect v4 library developers and integrators. It maps the pinned Pi durable contract to public concepts in this checkout, using [Pi commit `636703a0a4f2f4d8558d08f2308cb41109585bf5`](https://github.com/earendil-works/pi/tree/636703a0a4f2f4d8558d08f2308cb41109585bf5) as behavioral reference. Names and service shapes have been redesigned around Effect Schema, Context.Service, Layer, Scope, Stream, native AI and native Workflow.

The pinned behavioral contract and authorized native substitutions have been independently reviewed with passing repository-wide executable coverage, including regression, lifecycle and real-process restart tests. The links below identify that implementation and evidence. This is bounded to the pinned reference and exercised cases; it does not guarantee every future upstream scenario, remote provider entitlement or external unpatched installation. These libraries are developed in this checkout; the instructions assume no published npm release. See [the runnable example](../apps/example/README.md) for actual public import/Layer composition and [README attribution](../README.md) for adapted components and distributed MIT notices.

## Required pinned Effect patch

The workspace pins Effect `4.0.1` and applies [patches/effect@4.0.1.patch](../patches/effect@4.0.1.patch) through root [package.json](../package.json) `patchedDependencies`. Run `bun install` at the repository root before building. The patch covers native AI validation and native Cluster transaction readiness in source, JavaScript and declarations. Do not independently upgrade Effect/platform/provider packages without checking their compatibility and both seams. An external unpatched dependency does not provide these checkout-specific behaviors, and copying only package build output does not arrange the patch for that consumer.

### Native Cluster Activity transaction readiness

SQL-backed native recovery exposed a deadlock when a recovered Activity RPC acquired a storage transaction while waiting for its Activity definition, but the resumed Workflow prefix needed a SQL transaction before reaching `Activity.make`. The patch waits for Activity readiness **before** acquiring that transaction. The Activity body and reply persistence still use the native `ClusterSchema.WithTransaction` boundary. ClusterWorkflowEngine applies the readiness annotation automatically; application authors continue using ordinary Workflow/Activity APIs and Layers. It does not supply a harness scheduler, change external-effect replay guarantees or assert that every Cluster recovery interleaving is covered.

[NativeRestart.test.ts](../packages/durable/test/restart/NativeRestart.test.ts) and its [fixture](../packages/durable/test/restart/fixture.ts) cover two physical SIGKILL windows: reuse of a completed Activity result, and rollback/reexecution of an unfinished transactional Activity after a SQL-reading Workflow prefix. The recovered Activity result and independently read committed counter must both equal one. The example uses the same native SQL engine composition but checks normal completion/replay, not this fault window. This is a pinned dependency repair, not a claim that unpatched 4.0.1 or arbitrary future Effect versions provide equivalent recovery.

### Required Effect AI patch

Native Effect AI otherwise rejects undeclared tool calls while decoding a response. The patch adds `allowUnknownToolCalls`, enabled **only** together with `disableToolCallResolution: true`. It preserves an undeclared call's name and parameters for the caller to settle. The public opt-in requires both broad tool names and `unknown` parameter encoding: literal names or a narrow parameter payload type would be unsound once undeclared calls are permitted. This does not weaken the original declared tools' runtime codecs when a caller exposes a broad disabled-resolution signature around them. Known calls still use their declared parameter codecs, and strict default behavior is retained. It does not execute unknown tools or add them to the offered Toolkit. The generic [Executor](../packages/harness/src/Executor.ts) opts in when the durable caller owns tool resolution; unavailable calls receive committed tool-result entries and participate in `afterTools` ordering.

The [compiled example](../apps/example/src/main.ts) checks strict native generation/streaming rejection, rejection with the opt-in alone, and preserved native generation/streaming calls with both flags. [ParityRegression.test.ts](../packages/durable/test/workflow/ParityRegression.test.ts) includes undeclared-call settlement beside real parallel tools. The flag is a checkout-specific dependency patch, not an unmodified upstream Effect API promise. Consuming these packages elsewhere with unpatched Effect cannot provide complete unavailable-tool parity.

## Native substitutions and integration limits

Use `Workflow.make`, ordinary `toLayer` registration and native execute/poll/resume directly. Effect owns the execution engine, replay, timers and deferred state. The authorized substitution replaces Pi's generic task phases, checkpoint-version handover and no-progress engine. Domain projections still preserve ownership, holds, admission, cancellation and receipts. Chord-style observation is replaced by scoped Effect Streams and shared mounts. JSONL uses self-contained harness commit frames; neither it nor SQLite promises Pi file-format interoperability. A persistent domain store alone does not persist a native Workflow engine.

Recovery is checked with actual [SQLite killed-process tests](../packages/durable/test/restart/HarnessRestart.test.ts), [native primitive restart tests](../packages/durable/test/restart/NativeRestart.test.ts), and public close/resume tests at six harness boundaries with both Memory and SQL-backed Cluster engines. This distinguishes physical domain commits from native notifications/client completion. It does not make an external shell/API action exactly once. Safe tools may repeat before receipt commit; unsafe tools need interruption/reconciliation policy. Unknown workflow code is not silently reimplemented by a scheduler; register compatible native declarations/handlers to resume.

Account consent/refresh, native prompt conversion and media protocols use HTTP fixtures. Live sign-in, provider entitlement, paid inference and an installed CLI are unverified external integrations here. Model capabilities/prices are caller-declared; deferred operations are descriptor capabilities, not a claim every provider supports remote defer/fetch/cancel. The installed CLI's explicit transcript mode is approximate input rendering, not equivalent structured saved-role history. Unsupported features must surface typed errors. Recognized images in built-in `read` deliberately yield `unsupported_image`, matching the pinned reference tool; provider media handling for custom tool content is a separate capability.
